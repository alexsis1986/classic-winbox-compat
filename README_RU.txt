WINBOX 3.43 x64 -> ROUTEROS 7.25
Неофициальный набор для локального создания совместимой копии
Версия набора: 1.0.0 | 31 октября 2026 года

ВАЖНО: В ЭТОМ ZIP НЕТ ГОТОВОГО WINBOX.EXE.
Сборщик получает оригинальный WinBox 3.43 x64 с сайта MikroTik или использует
предоставленный тобой оригинал. Затем создаёт отдельный модифицированный EXE
на твоём компьютере. Старый WinBox заменять не нужно.

Здесь проверен алгоритм на искусственных данных и защитные проверки кода.
Реальный EXE в среде подготовки не был скачан или запущен. Windows-запуск
PowerShell и подключение к MikroTik не проверены. Это экспериментальная
совместимость, а не подтверждённая полная поддержка RouterOS 7.25.

БЫСТРЫЙ ЗАПУСК — WINDOWS 10/11 x64

1. Полностью распакуй ZIP, например в C:\Tools\WinBox3\.
   Не запускай CMD прямо внутри ZIP. Предпочтителен короткий путь.
2. Дважды щёлкни 01_BUILD_WINBOX.cmd.
   При первом запуске нужен интернет также для получения таблицы патчей
   из зафиксированного коммита автора. Код автора не запускается.
   Устанавливать Python и запускать от администратора не требуется.
3. При успешном завершении появится:
       WinBox3_Compat\winbox64.exe
   Открой его через 02_RUN_WINBOX.cmd. Этот запуск проверяет хеш EXE.

Сборка сама НЕ подключается к маршрутизатору и НЕ запускает WinBox.
Оригинал сохраняется отдельно:
    source\winbox64_original_3.43.exe

ВНУТРИ СБОРЩИКА

- Оригинальный EXE скачивается только с:
  https://download.mikrotik.com/routeros/winbox/3.43/winbox64.exe
- Таблица исправлений загружается как ТЕКСТ с raw.githubusercontent.com
  из зафиксированного коммита upstream (SHA-1 Git blob + fingerprint SHA-256).
  Удалённый Python-скрипт никогда не выполняется.
- Проверяются размер и SHA-256 оригинала.
- Проверяются исходные байты всех 20 участков, затем применяются изменения.
- Пересчитывается контрольная сумма PE.
- До сохранения EXE проверяется полный SHA-256 результата.
- Файл с другим содержимым на месте результата НЕ перезаписывается.
- Режима «force», отключения проверок и загрузки чужих готовых EXE нет.

КОГДА АВТОЗАГРУЗКА НЕ УДАЛАСЬ

Скопируй именно оригинальный winbox64.exe версии 3.43 x64 в папку source\
и снова запусти 01_BUILD_WINBOX.cmd. Нужен настоящий EXE, не ярлык .lnk.
Можно также перетащить оригинальный EXE на 01_BUILD_WINBOX.cmd.
Версии 3.42, 32-битная 3.43 и уже изменённые файлы не принимаются.
Сбой загрузки не обходится HTTP, зеркалами или отключением сертификатов.

ИКОНКИ

Сборщик ищет комплект icons.png, icons24.png, icons32.png в твоём локальном
кеше %APPDATA%\Mikrotik\Winbox\ и копирует их рядом с новым EXE в icons\.
Адресная книга, пароли, подключения и остальные файлы кеша не копируются.

Если кеша нет, EXE всё равно собирается, но часть иконок может отсутствовать.
Свой комплект старых иконок можно положить в source\icons\ и повторить сборку.
Не требуется понижать RouterOS ради иконок. Существующие разные файлы иконок
сборщик не заменяет. Новые пункты RouterOS могут не иметь подходящей иконки.

ОГРАНИЧЕНИЯ — ПРОЧИТАЙ ДО ПОДКЛЮЧЕНИЯ

Это старый интерфейс с обходами несовместимости, а НЕ WinBox 4 внутри WinBox 3.
Незнакомые WinBox 3 типы полей пропускаются, а не реализуются заново.
Могут отсутствовать новые Wi-Fi Labels, BSS On Time, высокоточные временные
поля NTP/Sniffer и новые диапазоны маршрутизации. Пользовательские skins
не применяются; права пользователя на самом RouterOS этим не расширяются.
Действия Power Cycle и Format Drive могут открыться без выбранного объекта.
Не применяй их, не проверив фактическую цель действия.

CMR, все функции hAP be3, подключение по MAC и будущие версии RouterOS
не входят в независимо проверенную матрицу этого набора. Для CMR и важных
изменений используй официальный WinBox 4. Совместимость с 7.26 и более
поздними версиями не обещается. Сохрани официальный WinBox 4 как резерв.

После изменения EXE исходная цифровая подпись MikroTik больше не соответствует
его содержимому. Это не официальный подписанный релиз MikroTik.
SmartScreen или антивирус могут его остановить. Набор не добавляет исключения,
не отключает Defender/SmartScreen и не изменяет доверенные сертификаты.
Не отключай защиту Windows ради этого набора.

CMD запускает только вложенный локальный PowerShell-скрипт с
-ExecutionPolicy Bypass для ОДНОГО процесса. Постоянная политика PowerShell
не изменяется. Это не обход корпоративных политик: при запрете скриптов
операция может не выполниться, и такой запрет не следует отключать.

Перед изменением реальной конфигурации сохрани backup/export привычным
официальным способом. Первую проверку лучше делать на тестовом устройстве
или учётной записью только для чтения. Сам набор этого не делает.
Обычный WinBox после запуска использует собственный штатный профиль;
изоляция его сохранённых сеансов этим набором не реализована.

ПРОВЕРКА И ЖУРНАЛ

03_VERIFY_FILES.cmd проверяет SHA256SUMS.txt и, если они уже есть,
исходный и модифицированный EXE. Проверка целостности — не цифровая подпись.

Журналы создаются в logs\. Они содержат пути, хеши, этапы сборки и ошибки,
но сборщик не запрашивает и не записывает пароль маршрутизатора.
При ошибке хеша, загрузки или записи сборка останавливается.
При отсутствии иконок выдаётся предупреждение, а не ложный отказ сборки EXE.

НЕОБЯЗАТЕЛЬНО: PYTHON

build_winbox.py — альтернативный сборщик для Python 3.9+:
    python build_winbox.py source\winbox64.exe
Он при необходимости импортирует таблицу патчей из зафиксированного источника
(upstream, не выполняя скачанный код). Сам EXE он не скачивает и иконки не копирует. Для атомарной публикации использует
жёсткую ссылку: NTFS/ext4 подходят; на FAT32/exFAT используй Windows-сборщик.
Сетевых библиотек и дополнительных Python-пакетов ему не требуется.

Для повторения локальных тестов:
    python scripts/import_upstream.py
    python -m unittest discover -s tests -v
См. VALIDATION_REPORT_RU.txt и tests\unit-tests.txt.

УДАЛЕНИЕ

Закрой модифицированный WinBox и удали распакованную папку набора.
Исходный WinBox на рабочем столе/в другой папке набор не заменяет.
Сам WinBox может сохранить обычные настройки в своём штатном профиле.
