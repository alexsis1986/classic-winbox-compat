# Установка на macOS — Classic WinBox 3.43 через Wine

**Исходники Preview 0.1.0-preview.1. Это не нативный Universal/ARM-клиент.**

## 1. Требования и Wine

Нужны Python 3.9+ и доверенная macOS-сборка Wine с поддержкой Windows x64, установленная вместе со всеми её зависимостями. Минимальная macOS определяется выбранным Wine; версия в метаданных нашего .app не является подтверждением совместимости.

Для Intel Mac используется совместимый x86-64 Wine. На Apple Silicon описанный путь с Intel Wine дополнительно требует Rosetta 2; при необходимости используйте штатный запрос установки Apple. Наши скрипты не устанавливают Rosetta и не принимают её лицензию за вас. Apple ограничивает общую доступность Rosetta версиями macOS до 27 включительно; поддержка macOS 28+ не обещается.

Ручная установка описана разработчиком сборок Wine:

- https://github.com/Gcenx/macOS_Wine_builds
- https://github.com/Gcenx/macOS_Wine_builds/releases

Прочитайте требования именно выбранного релиза к ОС и зависимостям. Простого копирования Wine может быть недостаточно для установки нужных frameworks. На 31.10.2026 cask `wine-stable` в Homebrew помечен **disabled**; не рассчитывайте на старую команду `brew install --cask wine-stable` и не обходите проверки безопасности ради принудительной установки.

Wine не включается в пакет и не изменяется. При предупреждении о вредоносном ПО остановитесь. Не отключайте Gatekeeper и не удаляйте quarantine рекурсивно. Ссылки Apple и Homebrew — в SOURCES.md.

## 2. Исходники и локальный EXE

Распакуйте публичный ZIP исходников оболочек и откройте каталог с `build_packages.py`. Другой вариант:

```bash
git clone https://github.com/alexsis1986/classic-winbox-compat.git
cd classic-winbox-compat/platforms
python3 --version
```

Нужен ваш законно полученный и локально подготовленный `WinBox3_Compat/winbox64.exe`, соответствующий существующему Windows-комплекту v1.0.0. Перенесите только EXE, без сессий и паролей. Неизменённый файл производителя не является входом для этого упаковщика. Оболочка не даёт прав на модификацию и распространение чужого ПО; Windows-патчер остаётся отдельным компонентом с описанными в проекте нерешёнными вопросами разрешений.

```bash
shasum -a 256 "$HOME/Downloads/winbox64.exe"
```

Ожидаемый SHA-256 исправленного EXE:

```text
ac40890431762b588a7b7777d1ad48c54751dbfa2a3868450222dce757ec496d
```

## 3. Локальная сборка приложения

```bash
python3 build_packages.py --audit-source
python3 build_packages.py --exe "$HOME/Downloads/winbox64.exe" --out ./private-build
cd private-build/ClassicWinBox343-macOS-Wine-preview0.1.0
bash VERIFY_FILES.sh
bash 01_CHECK.command
```

Укажите путь к своему EXE. Существующие результаты не перезаписываются. Создаются частные архивы обеих платформ. Они содержат ваш EXE: **не загружайте их в GitHub без необходимых прав**. Публичный архив исходников собирается отдельно через `--source-only`.

`01_CHECK.command` проверяет приложение именно в текущей папке, а не старую копию в Applications. WinBox и подключение к роутеру он не запускает. Если вы перенесли на Mac уже локально собранный пакет, распакуйте его штатным архиватором, откройте его папку в Terminal и начните с двух последних команд выше.

## 4. Установка и открытие

```bash
bash Install.command
open "$HOME/Applications/Classic WinBox 3.43.app"
```

Установщик копирует весь bundle в `~/Applications`, восстанавливает права запуска и отказывается заменять существующее приложение. Sudo не нужен. Альтернатива — перетащить целый `.app` в пользовательскую папку Applications. Не вынимайте отдельные файлы из `Contents`.

Приложение **не подписано Developer ID и не нотарифицировано Apple**. Изменённый Windows EXE тоже не соответствует исходной Authenticode-подписи производителя. Контрольная сумма не заменяет проверку безопасности и подпись. macOS может заблокировать запуск; прочитайте штатную инструкцию Apple и принимайте решение только после проверки происхождения. Скрипты не меняют Gatekeeper/quarantine. При предупреждении о вредоносном или повреждённом файле не продолжайте.

## 5. Нестандартная установка Wine

Проверяются PATH, известные Wine-bundle в `/Applications` и `~/Applications`, типичные расположения Homebrew/MacPorts. Явное указание для диагностики:

```bash
CWC_WINE_BIN="/absolute/path/to/wine" bash 01_CHECK.command
```

Для запуска из Finder создайте `~/Library/Application Support/ClassicWinBox343/wine-path.txt` и запишите абсолютный путь к исполняемому Wine одной строкой, без кавычек и аргументов. Может требоваться именно штатный запускатель runtime, загружающий его зависимости. Паролей в файле быть не должно.

## 6. Данные, ограничения и удаление

Профиль Wine: `~/Library/Application Support/ClassicWinBox343/wineprefix/`.
Личный журнал последнего запуска: `~/Library/Application Support/ClassicWinBox343/logs/last-launch.log`.

Отдельный профиль — не защитная песочница. Сессии не публикуйте; логи обезличивайте. Адрес и пароль вводятся только в WinBox. Для первой проверки используйте тестовый роутер/учётную запись только для чтения и IP. Neighbors/MAC, отрисовка и операции RouterOS на macOS ещё не подтверждены. Фирменные иконки и шрифты не включены. Новых обработчиков RouterOS оболочка не добавляет.

Для удаления уберите `.app` из `~/Applications`. Профиль оставьте, если нужны сессии; автоматического удаления данных нет.

**Проверки:** структура пакетов и скрипты тестируются с имитацией Wine. Реальные macOS, Rosetta, Gatekeeper, Wine GUI и операции роутера не сертифицированы. Первоисточники: [SOURCES.md](SOURCES.md).
